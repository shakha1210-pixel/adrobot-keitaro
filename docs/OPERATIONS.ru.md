# Техническая поддержка, логи и диагностика

Практическое руководство для разработчика или оператора локального экземпляра Adrobot.

## 1. Где смотреть логи

При стандартном запуске через Uvicorn логи выводятся в тот же терминал, где запущен сервер. Формат:

```text
2026-11-21 12:00:00 INFO    app.module: сообщение
```

Уровень по умолчанию — INFO. Приложение не настраивает отдельный файл логов и не реализует ротацию файлов: если нужна долговременная история, настройте сбор stdout/stderr средствами ОС, Docker или платформы деплоя.

### Windows PowerShell: сохранить вывод в файл

```powershell
.\.venv\Scripts\python.exe -m uvicorn app.main:app --reload 2>&1 |
  Tee-Object -FilePath .\adrobot-console.log
```

### Linux / macOS: сохранить вывод в файл

```bash
uvicorn app.main:app --reload 2>&1 | tee -a adrobot-console.log
```

Не публикуйте логи без проверки: в них могут оказаться внутренние URL, названия кампаний и диагностические данные. API-ключи, пароли и содержимое `.env` отправлять нельзя.

## 2. Проверка состояния

В отдельном терминале выполните:

```bash
curl -i http://127.0.0.1:8000/health
curl -i http://127.0.0.1:8000/health/live
curl -i http://127.0.0.1:8000/health/ready
```

- `/health` — сводный статус зависимостей.
- `/health/live` — отвечает ли процесс.
- `/health/ready` — готово ли приложение работать с БД и Keitaro; при проблеме может вернуть 503.

Проверка конфигурации API: `http://127.0.0.1:8000/api/meta`. Swagger: `http://127.0.0.1:8000/docs`.

## 3. Связать HTTP-ошибку с логами: X-Request-ID

Каждый HTTP-ответ содержит `X-Request-ID`. Если клиент прислал этот заголовок, приложение использует его; иначе генерирует короткий ID.

```bash
curl -i http://127.0.0.1:8000/health
```

Найдите в заголовках `X-Request-ID` и укажите его в обращении. Для повторного запроса можно передать свой ID:

```bash
curl -i -H "X-Request-ID: support-check-001" \
  http://127.0.0.1:8000/health
```

Важно: текущий формат логирования не добавляет request ID автоматически в каждую строку. Заголовок помогает коррелировать запрос на уровне клиента и ответа, но не является полноценным distributed tracing.

## 4. Частые сценарии диагностики

| Симптом | Проверки |
|---|---|
| Сервер не стартует | Активно ли виртуальное окружение; установлены ли зависимости; свободен ли порт 8000 |
| `/health/ready` → 503 | Сверьте `DATABASE_URL`, доступность БД, `KEITARO_BASE_URL` и API key |
| `keitaro_unavailable` | DNS/сеть, TLS, URL трекера, таймаут |
| `keitaro_error` | Посмотрите статус и диагностическое сообщение в серверном терминале; проверьте права API key |
| `keitaro_ambiguous` | Проверьте Keitaro вручную до повторения операции |
| Не разрешаются домен/группа/источник | Сверьте `DEFAULT_DOMAIN`, `DEFAULT_GROUP`, `DEFAULT_SOURCE` с именами в Keitaro |
| Миграция не проходит | `alembic current`, затем проверьте `DATABASE_URL` и вывод Alembic |

## 5. Безопасный порядок действий при неоднозначной операции

1. Остановитесь — не повторяйте POST автоматически.
2. Сохраните текст ошибки, время и HTTP request ID.
3. Откройте Keitaro и проверьте, создалась ли кампания или поток.
4. Если кампания создана частично, проверьте её фактические потоки и состояние.
5. Только после проверки решайте, нужно ли повторять действие или исправлять конфигурацию.

## 6. Локальная проверка перед передачей проекта

Windows:

```powershell
.\scripts\check.ps1
```

Кроссплатформенно:

```bash
ruff check .
ruff format --check .
pytest -v
node --check static/app.js
alembic upgrade head
```

Ожидаемое количество тестовых функций в текущем наборе — 58. Фактический результат выполнения pytest зависит от окружения и должен быть подтверждён локальным запуском/CI.

## 7. Шаблон обращения за помощью

Подготовьте:
- ОС и версию Python;
- способ запуска (PowerShell, shell, Docker/другое);
- точное время ошибки и шаги воспроизведения;
- endpoint и HTTP status;
- `X-Request-ID`, если есть;
- обезличенный фрагмент логов вокруг ошибки;
- результат `/health` и `/health/ready`.

Не прикладывайте API key, пароль, полный `.env`, персональные данные или неотредактированные секреты.

## 8. Эскалация

Если ошибка касается структуры Keitaro API, сверяйте фактический payload с версией Admin API вашего трекера. Архитектурные решения и границы интеграции описаны в [архитектуре](ARCHITECTURE.ru.md), а параметры приложения — в [профессиональном руководстве](PROFESSIONAL.ru.md).
